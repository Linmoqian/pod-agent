# 验证规范

## 原则

- 行为、接口、数据格式、依赖、构建、权限与 UI 改动必须验证。
- 优先使用项目已有命令；验证范围覆盖本次改动及直接影响面，高风险改动扩大回归。
- 修复缺陷时先用测试或最小步骤复现，再修复并验证回归。
- 只汇报实际执行过的命令和结果；失败、跳过或依赖硬件的范围必须如实说明。
- 纯 Markdown、拼写或不参与执行的注释改动可免完整构建，但要检查差异、链接和示例。

## 最小验证矩阵

| 改动 | 最小验证 |
| --- | --- |
| React/TypeScript | `npx tsc --noEmit`，再验证受影响交互 |
| Rust 纯逻辑 | `cargo fmt --check`、相关单元测试、`cargo clippy --all-targets -- -D warnings` |
| SQLite schema/查询 | 新旧数据库迁移测试、合法/边界/错误输入 |
| Tauri command/事件/channel | Rust 测试、前端类型检查、真实 IPC 路径 |
| 相机/YOLO | 无模型、模型加载失败、正常帧、停止与资源回收；硬件依赖单独说明 |
| LLM/tool calling | 无工具、合法工具、未知工具、参数错误、流式分片、超时与断网 |
| 文档 | `git diff --check`、链接/命令/术语人工核对 |

最终汇报包含改动、实际验证、未覆盖范围、仍存风险与提交状态。
